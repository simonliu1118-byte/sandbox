## 0. 前次對話最後的明確指示（接手時優先閱讀）

使用者最後確認：

1. **飛比的報價不需要留下歷史紀錄**，不建報價資料庫、價格歷史、追蹤或匯出紀錄。
2. **不研究、不追蹤飛比的資料更新時程**。前端清楚標示「來源：飛比」、「第三方參考價／非酷澎當前即時價」、「來源價格更新時間未確認」即可；不得誤稱為當前可成交價格。
3. 在**目前 momo 一頁式原型**增加**另一個獨立查詢項目**（暫稱「酷澎／飛比參考價」），與原本 momo 查詢及結果清楚分開；不可把飛比資料混入 momo 的最低價、均價、中位數、標準差或同規格統計。
4. **不急著拆獨立網站**。先在現有原型驗證實際可行性，細部優化、站點拆分及資料庫整合留待後續。
5. 先前也已明確取消人工分類的**匯出／匯入**功能；不可重新加入。

### 重要語意

- momo 區顯示「當次向 momo 公開搜尋介面取得的展示價」，不宣稱實際結帳價。
- 飛比區如成功取得數字，固定顯示「飛比收錄的酷澎參考價（非當前酷澎直接報價）／來源價格更新時間未確認」；若無有效可辨識價格，顯示「未取得可用參考價」，不可拿商品索引文字或不明數字充當價格。
- 「本次查詢時間」若在畫面顯示，只是程式讀取資料的時間，**不是**飛比來源價格的最後更新時間。
- 當次查詢僅用於畫面展示；不持久保存報價、查詢歷史或價格快照。

## 4. 接續工作：只新增一個互相隔離的「酷澎／飛比參考」查詢項目

**目標：** 在同一頁網站同時提供原本 momo 查詢與新的飛比參考查詢入口，兩邊分別輸入關鍵字與顯示結果。此階段不拆站、不重構既有 momo 統計系統。

### 實作順序與驗收基準

1. **先確認資料可解析性：** 以允許的單次一般公開查詢檢視飛比搜尋結果，辨識與酷澎有關的商品標題、參考價、連結及可核對的規格資訊。若無法建立商品和參考價的可靠對應，不可硬接成「可查價成功」。
2. **新增獨立查詢入口與結果區：** 建議原頁上設「momo 查價」及「酷澎／飛比參考」兩個清楚分離的表單／區塊；飛比查詢不得自動觸發 momo 查詢，反之亦然。
3. **顯示來源與限制：** 每筆飛比結果要有商品描述（若取得）、第三方參考價（若可信）、來源連結，以及醒目的固定說明「來源價格更新時間未確認／非酷澎即時售價」。沒有可驗證的價格時如實顯示未取得，不以 0 元表示。
4. **資料與統計隔離：** 不將飛比項目丟進 `catalog_core.js` 的 momo 同型號價格分群或任何 momo 統計；飛比資料不視為與 momo 的同規格精準可比價。
5. **不加需求：** 不做價格歷史、定時查價、更新週期追蹤、資料匯出／匯入、Cloudflare D1、登入購物、會員優惠、下單或獨立站架構整理。
6. **保留合理防護：** 單次請求，遇 403、429、流量驗證或異常停止，不自動重試、繞過驗證、輪換代理或使用使用者／公司網路；記錄錯誤狀態即可，勿把被阻擋寫成查價成功。
7. **測試後回報真相：** 補充離線解析與分流測試，既有 momo 流程不得回歸；在 PR 內進行 GitHub 驗收。Vercel Preview 是否能即時取得結果需額外實測確認，不能以單元測試代替。

### 目前不應做的事

- 不合併 PR #31、不修改 `main`、不部署正式站；若要更新 Preview，先確認目前部署和使用者授權範圍。
- 不把酷澎公開頁／Google 快取／飛比收錄價當成酷澎現在的即時有效售價。
- 不為了完成這個小型原型先設 D1 或重新設計整套系統。

## 5. 蝦皮主線保留，不與本次飛比 UI 工作混在一起

- 蝦皮最理想為 **TW/TWD + 商品 ID + SKU/Model ID + 規格名稱 + 個別售價 + 來源網址 + 擷取時間** 的完整逐規格售價。
- 僅有商品最低／最高價或範圍時只能作商品層級備用，不能聲稱是指定規格價格；**備用來源必須長期零費用**，並確認免費額度與硬性停用規則。
- 高價 Octoparse 正式方案已依使用者決定排除；第三方範例不等於臺灣實測通過。
- 與本次單頁飛比參考區無直接依賴，暫不擴大蝦皮研究或採購。
