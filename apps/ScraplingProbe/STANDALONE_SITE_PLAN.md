## 3. 獨立網站第一階段 MVP 決策

1. 同一個一頁式介面維持 **momo／飛比蝦皮／飛比酷澎三個分開的查價入口及結果**；不將查價程式直接合併進 CYWEB。未來是否由 CYWEB 提供入口連結，另行決定。
2. **只維護一套飛比搜尋／HTML 解析／流量控制／10 分鐘暫存邏輯**，依來源分類蝦皮與酷澎；不能為每個平台複製整套程式。
3. 三來源共用規格解析、人工修正、標記不使用、動態篩選、單價及同規格群組統計**同一套前端元件**，但分類資料與價格比較結果**必須依平台隔離**。
4. 飛比是**第三方收錄的商品級參考價，來源價格更新時間未知**。未人工確認單一型號、尺寸、包裝入數與單位之前，不得進入同規格參考單價統計；即使人工分類，也不能稱為已驗證的逐 SKU 即時價或結帳價。
5. momo 的後端 1～5 頁查詢，與飛比「僅在這次已取到的候選商品間切換頁數」必須清楚區別；不可將客戶端分頁冒充已讀取飛比後續頁。
6. 仍是**私人、零額外付費的原型**。不記錄歷史價格，不做匯入／匯出、排程追蹤、會員登入、購買、代理輪換、驗證繞過，暫時不啟用 D1 或 Grok BOT。

## 4. 技術責任分工（避免第二套流程）

| 功能 | 現有主責檔案 | 拆站時要維持的界線 |
| --- | --- | --- |
| momo 查詢及 Flask 路由 | `site/app.py` | 一次主動請求，明確 HTTP 及錯誤狀態，與飛比資料分離 |
| 飛比搜尋與來源辨識 | `site/feebee_search.py` | 唯一飛比解析器；同關鍵字切換來源可使用記憶體快取 |
| 同規格可比性與統計 | `site/static/catalog_core.js` | 三來源共用；飛比資料另外要求人工確認規格 |
| 人工分類及顯示 | `site/static/catalog_ui.js`、`site/templates/index.html` | 一套 UI renderer，依來源獨立 localStorage 規則；不可重複綁定三份互相競爭的流程 |
| 執行環境與安全 | `site/vercel.json`、Vercel 環境變數 | 私人存取控制；密碼、token 永不進 Git；正式上線前另行核對 |

目前 localStorage 是**瀏覽器本機資料**，不是跨裝置同步；換網域、裝置或清除網站資料可能失去人工分類。將來確認需要跨裝置共用分類才評估 D1，且 D1 是資料庫，不是執行抓價的 Worker。
