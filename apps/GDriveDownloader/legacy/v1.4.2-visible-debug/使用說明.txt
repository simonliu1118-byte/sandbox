一、開始使用
1. 將壓縮檔完整解壓縮到一個新的資料夾，請勿直接在 ZIP 內執行。
2. 雙擊「GoogleDrive影片下載器.exe」。
3. 首次啟動會自動展開內建元件，約需數秒至數十秒；請勿重複點擊。
4. 在網址列右側選擇畫質，將 Google Drive 影片網址貼到輸入列後按 Enter；任務會自動開始。
5. 公開影片不必登入；需要權限的私人影片會在佇列中等待登入。

二、主視窗與 Google 登入
1. 主介面現在是獨立的 Windows 應用程式視窗，不會再以 Edge 應用程式視窗顯示。
2. 主視窗使用 Windows WebView2 顯示介面；Google Drive 登入及播放來源則使用程式指定的受控瀏覽器。
3. 有安裝 Google Chrome 時程式固定優先使用 Chrome；沒有 Chrome 才改用 Edge，主畫面會顯示目前使用者。
4. 按右上角「登入 Google（Chrome）」或「登入 Google（Edge）」，只能在該視窗中完成授權；不要改到一般瀏覽器另外登入。
5. 登入視窗、影片播放來源與實際下載授權共用同一個瀏覽器執行個體及同一份專屬設定檔。
6. 登入成功後按鈕顯示「✓ 已登入 Google（Chrome/Edge）」；點擊該按鈕可切換帳號。
7. 專屬設定檔會長期保存登入狀態，且程式不會記錄你的 Google 密碼。
8. 第一次使用 1.1.1 時請在程式指定的 Chrome 重新登入一次；一般 Chrome 視窗既有的登入不會直接混用。
9. Google 仍可能因密碼變更、權限撤銷或安全驗證要求重新登入。

三、下載規則
- 任務加入後自動開始；超過設定的同時處理數量時會進入佇列。
- 優先度按鈕依序切換：一般 → 高 → 低 → 一般。
- 優先度只調整等待中任務的順序，不會中斷已開始的任務。
- 每個任務只建立一個 Drive 播放頁面，程式會直接連線到該分頁自己的 DevTools WebSocket，不再透過瀏覽器層的自動附加或子工作階段轉送事件。
- 固定執行順序為：直接連線分頁 → Network.enable → Page.enable → 導航到 Drive 影片 → 立即靜音播放 → 收集 videoplayback。
- 網路監聽與播放操作使用同一個分頁及同一條 DevTools 連線，等同手動開啟該分頁的開發人員工具查看 Network。
- 1.4.2 可視除錯版沒有播放器預熱、延遲監聽、重建播放器或多開 Drive 分頁。
- 單一 Drive 分頁會接收自身及內嵌播放器 iframe／worker 的 Network 事件，行為與該分頁 DevTools 的整合 Network 清單一致；不會監聽其他分頁。
- 程式同時使用即時網路事件與播放器資源紀錄兩條通道收集來源；其中一條沒有收到事件時，另一條仍可取得 videoplayback 網址。
- 每一筆原始 videoplayback 網路請求都保留為候選；即使移除 range 與 ump 後網址相同，也不會把不同請求合併成一筆。
- 來源擷取頁面會以正常大小顯示在畫面上、切到前景並全程靜音，方便直接觀察 Drive 頁面與播放器狀態。
- 任務失敗或等待登入時不會自動關閉該 Chrome 分頁；檢查完畢可自行關閉分頁，或關閉主程式一次結束受控瀏覽器。
- 取得 Google Drive 標題後會立刻顯示在任務清單，不必等待來源收集結束。
- 網址列可選擇：最高可用、1080p、720p、480p、360p、播放器自動；選擇會套用到新加入的任務。
- 播放器永遠維持 Google Drive 預設的 Auto；程式不會開啟設定、不會點選畫質、不會為畫質操作移動滑鼠。
- 程式只負責開始播放並監聽 Auto 實際產生的 videoplayback，再依每筆來源的 mime 與 itag 分類。
- 每一筆音訊及視訊來源都會立即顯示在任務下方，包含順序、itag、辨識畫質及來源大小；重複請求也分開列出。
- 「最高可用」會等待設定中的「畫質確認時間」（預設 60 秒）：360p 先保留；取得 720p 後仍等候 1080p；若期限內取得 1080p 或以上便立即鎖定並開始下載，否則期限結束後鎖定當時最高的 720p 或以上來源。
- 最高可用在 720p 已開始下載後仍會繼續監聽；若後來出現 1080p，會取消 720p 並改為下載 1080p，之後只接受 1080p。
- 指定 720p／1080p 等畫質時，第一筆相符來源出現便立即鎖定並下載；第二階段新出現的非指定畫質來源不再列入或下載。
- 指定畫質尚未出現時不會把第一個 360p 來源當成最高畫質，也不會擅自降級下載。
- 如果使用者要求較高畫質，但程式只辨識到較低畫質，會暫停視訊下載並要求確認；音訊下載不受影響。
- 確認視窗可直接開啟同一個播放器查看畫質。若使用者確認影片確實有指定畫質，任務會標記為「程式BUG」、不下載較低畫質，並保留 Chrome 除錯分頁及寫入 BUG.log。
- 若使用者確認要改用其他畫質，程式會列出所有已辨識畫質供選擇；只有明確選定後，該畫質視訊才會進入下載流程。
- 來源收集與下載測速會同時進行，不必等來源全部收集完才開始下載。
- 每筆候選會先依請求網址的 mime／itag，以及 Chrome 回應的 MIME／Content-Type 判斷音訊、視訊及解析度；請求階段無法分類的來源會在收到回應後重新分類，不會被提前丟棄。
- 音訊與視訊完全分開判定：音訊一經確認就直接進入音訊下載流程，不等待視訊畫質；不符合要求畫質的視訊則不會進入下載。
- 音訊、視訊各自在第一個合格來源出現時只啟動該一筆下載及判速；初始階段不會平行開啟三筆候選。
- 第一筆確認慢速後才保留為保底並逐一測試下一筆；同一時間最多只有「保底一筆＋正在測試一筆」。
- 指定畫質或音訊找到正常速度來源後，會停止收集該類的新來源；最高可用若目前僅為 720p，仍會等待後來出現的 1080p。
- 音訊與視訊都找到正常速度來源，或其中一類已下載完成後，會立即停止整個來源收集流程。
- 「畫質確認時間」只限制第一階段的畫質決定，可在設定中調整為 10–300 秒；開始下載後，慢速測試與尋找同畫質高速來源不設時間限制。
- 設定中已移除「略過起始秒數」與「最長來源收集時間」。
- 每個來源膠囊會以顏色顯示狀態：灰色為未使用、綠色為下載／測速／高速／完成、黃色為慢速保底、紅色為已取消或失敗。
- 若來源本身已是包含音訊的 MP4，程式會直接下載，不再誤判為缺少權限。
- 實際檔案傳輸直接使用受控 Chrome/Edge 的原生網路工作階段；播放、授權及下載不再分屬不同的 HTTP 用戶端。
- videoplayback 會由同一個已登入的 Chrome 以原生 HTTP/2、TLS 與瀏覽器授權連線下載，再立即將回應內容串流寫入檔案；不再改用速度可能與手動 Chrome 下載不同的 Bun 連線。
- 錯誤訊息會明確區分「沒有收到候選來源」與「已找到候選、但全部下載失敗」，並保留最後一個實際 HTTP 或連線錯誤。
- 媒體資料由瀏覽器帶入目前的登入憑證後串流交給程式寫檔，避免只複製 Cookie 仍被 Google 回覆 HTTP 403。
- 若仍遇到 403，程式會自動重新擷取一次；再次失敗時會等待你在指定瀏覽器重新登入。
- 成品檔名採用 Google Drive 中的影片標題。
- 同名檔案不會覆蓋，會自動加上 (1)、(2) 等編號。

四、慢速來源切換
- 預設低於 50 KB/s 視為慢速，可在設定中調整。
- 0 B 不屬於慢速下載；候選連線預設等待 60 秒仍未收到第一個位元時，才會取消該候選並嘗試下一個；可在設定中調整為 5–120 秒。
- Chrome 原生下載分頁等待回應標頭的時間也改為 60 秒，不會在來源測試時間尚未結束前先行失敗。
- 收到第一個位元後才開始測速，預設平均速度觀察時間為 60 秒，可在設定中調整為 3–300 秒。
- Chrome 控制連線失效時會停止該次來源測試；尚未真正開啟的後續來源保持灰色「未使用」，不再被連鎖誤標為失敗。
- 只有真正收到媒體資料後，才開始平均速度觀察時間的計算，不再略過額外起始秒數。
- 來源連線結束但檔案仍為 0 B 時會判定失敗，不會建立空白成品。
- 來源1慢速時會繼續下載，保留為保底。
- 每當播放器產生來源2、來源3等新來源時，程式會立刻逐一測試；仍然慢速就取消該來源，再等待下一個。
- 找到正常速度的來源後，取消來源1並改用正常來源，同時停止收集該類的新來源。
- 尋找高速來源不設時間上限；如果一直沒有高速來源，來源1會繼續下載至完成，不會浪費先前已下載的資料。
- 音訊與視訊各自獨立執行上述判斷。

五、關閉程式
- 有下載或合併工作進行時，關閉視窗會出現確認警告。
- 確認關閉後會取消未完成工作並清除暫存檔。
- 下次開啟不會續傳。
- 按單筆「取消」或「取消全部」時會先安全停止來源擷取、音訊與視訊下載，待瀏覽器串流及檔案寫入完成收尾後才移除任務，不會因 AbortError 異常結束程式。

六、程式檔案與紀錄
- 請將主 EXE 與 runtime_payload.tar.xz 保留在同一資料夾。
- 首次成功啟動後會產生 runtime 資料夾，請勿刪除或移動其中檔案。
- 程式從啟動開始就在 EXE 同層的 log 資料夾寫入紀錄，不會把 log 放到其他位置。
- startup.log 記錄啟動、解壓縮、實際路徑及 Windows 錯誤代碼；app.log 記錄主程式、登入、來源擷取與下載狀態；使用者確認程式未抓到實際存在的指定畫質時，另寫入 BUG.log。
- 預設成品位置：Windows「下載」資料夾內的 GoogleDriveVideos。
- 設定及登入資料：%LOCALAPPDATA%\CYDriveDownloader

七、問題排查
- 程式會自動在背景靜音播放，不需要你手動按播放；任務提示會分別顯示音訊與視訊的來源數及判速狀態。
- 1.4.2 可視除錯版沒有播放器固定預熱、畫質選單操作與重建工作階段；來源收集從頁面載入及播放開始後立即進行。
- 頁面掃描只辨識播放鍵與座標，不會自行點擊；每輪最多送出一次受信任滑鼠點擊，並排除暫停按鈕。點擊後等待一秒確認，偵測到 playing=1 後停止按鍵。
- 若仍找不到來源，請不要手動關閉保留的 Chrome 分頁，先截圖該分頁實際畫面；也可測試手動按下播放後，程式的來源數是否開始增加。
- app.log 會依序記錄「已直接連線 Drive 分頁 DevTools」、「Network.enable 已完成」、「分頁已導航」及播放器 media/playing/button 狀態變化。
- 任務提示與 app.log 會顯示該 Drive 分頁實際看到的 videoplayback 數量。
- app.log 會逐筆記錄候選的 mime、itag、解析度與實際回應 Content-Type。
- app.log 與任務清單會逐筆列出音訊／視訊來源的 itag、辨識畫質、MIME 與大小，方便直接對照 Chrome Network。
- 程式不會只因「未取得完整音訊與視訊」就顯示沒有權限；它會顯示實際的來源或下載錯誤。
- 若程式無法開啟或任務失敗，請提供 EXE 同層 log 資料夾中的 startup.log 與 app.log。
